# Contributing to VSTodo

Thank you for your interest in contributing to VSTodo!

## Getting Started
1. Fork the repository.
2. Clone your fork.
3. Create a feature branch.
4. Make your changes.
5. Run the available tests.
6. Submit a Pull Request.

## Development Guidelines
- Write clean, readable Go code.
- Follow the existing architecture.
- Add tests for new functionality.
- Update documentation when needed.
- Avoid unnecessary dependencies.
- Never commit binaries or local repository data.

## Commit Messages
Use descriptive commit messages:
- feat: add new functionality
- fix: resolve a bug
- docs: update documentation
- test: add tests
- refactor: improve code structure

## Bug Reports
Include a description, reproduction steps, expected behavior, actual behavior, and relevant error messages.

## Feature Requests
Explain the problem, proposed solution, and expected benefits.

## Pull Requests
Keep changes focused, explain your modifications, and ensure relevant tests pass.

## Code of Conduct
Be respectful, constructive, and professional.

By contributing, you agree that your contributions are provided under the project's MIT License.
